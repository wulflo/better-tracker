# Better Fitness Tracker 0.9.17

Release de corrección para Linux. No cambia el formato de la bóveda (`omega/`)
ni el de las copias (`longlife/`).

### Ventana sin marco estable

- Arrastrar o redimensionar la ventana ya no acumula artefactos grises ni deja
  el escritorio congelado. El arreglo sigue al de Study Planner: se quitaron
  los `backdrop-filter`, la barra superior y la lateral usan color opaco en vez
  de `rgba(...)` y los tiradores de redimensionado se ocultan cuando la ventana
  está maximizada.
- `splash` y `main` declaran `transparent: false` y `backgroundColor: #0d0a13`,
  así el compositor no mezcla un visual ARGB en cada fotograma.
- Afecta a todos los formatos de Linux, AppImage incluido.

### NVIDIA propietario

- Si se detecta el driver `nvidia` (por `/proc/driver/nvidia`, `/sys/module/nvidia`
  o el symlink de `/sys/class/drm/card*/device/driver`), la app fija
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` antes de inicializar GTK.
- Con la serie 580 el `WebKitWebProcess` moría con `SIGSEGV` dentro de
  `libnvidia-eglcore`; el compositor quedaba esperando fences inválidos, la
  ventana mostraba artefactos y el equipo se congelaba. La detección cubre
  portátiles híbridos y funciona también dentro de Flatpak y Snap.
- Cualquier variable de renderizado fijada por la persona usuaria
  (`WEBKIT_DISABLE_DMABUF_RENDERER`, `WEBKIT_DMABUF_RENDERER_FORCE_SHM`,
  `WEBKIT_DISABLE_COMPOSITING_MODE`, `__NV_DISABLE_EXPLICIT_SYNC`,
  `LIBGL_ALWAYS_SOFTWARE`) desactiva la detección automática.

### Instancia única

- `tauri-plugin-single-instance` enfoca la ventana existente y cierra la segunda
  ejecución. Evita ventanas apiladas, procesos WebKit duplicados y escrituras
  concurrentes en la misma bóveda.

### Flatpak

- El runtime pasa de `org.gnome.Platform` 48 a 51. Con GNOME 48 (WebKitGTK
  2.48) el `WebKitNetworkProcess` no lograba arrancar dentro del sandbox y la
  app moría con `SIGKILL` a los ~400 ms: se instalaba pero no abría, sin ningún
  error en consola. Desde GNOME 49 el runtime trae WebKitGTK 2.50, donde el
  fallo está corregido.

### Compilación

- Linux se compila en `ubuntu-24.04` (antes 22.04), igual que Study Planner: el
  AppImage empaqueta el WebKitGTK del runner y el de 22.04 era demasiado viejo.
- Contrapartida: los `.deb` y `.rpm` de esta release requieren **glibc 2.39 o
  superior** (Ubuntu 24.04+, Debian 13+). El AppImage y el Flatpak no dependen
  de la glibc del sistema.
- El Flatpak se compila con la imagen `gnome-51`, en línea con el runtime.

### Verificación

- `cargo check`, `cargo test`, `cargo clippy -- -D warnings` correctos.
- `npx tsc --noEmit` correcto y 67 tests de frontend en verde.
- `npm run build` correcto.
- Flatpak 0.9.16 ejecutado contra los runtimes 49, 50 y 51: arranca, carga la
  interfaz y escribe la configuración; contra 48 muere con `SIGKILL`.

### Nota de actualización

- Los datos existentes se conservan intactos: solo cambian el entorno de
  renderizado, el empaquetado y la versión del runtime de Flatpak.
