# Better Tracker 0.9.9

Sustitución completa del escáner de códigos de barras por una entrada manual de
dígitos, integrada en Ingesta.

### Ingesta: código de barras manual

- Campo **«Código de barras»** siempre visible bajo el buscador de alimentos.
- Se escriben o pegan entre 6 y 14 dígitos y se pulsa **Buscar**; Enter también
  envía, así que funciona con lectores USB/Bluetooth que teclean el código.
- Se limpian espacios, guiones y otros caracteres no numéricos al pegar.
- Se mantiene el flujo completo: base local → catálogo local → Open Food Facts →
  formulario de alimento nuevo con el código ya rellenado.
- Se mantiene la validación del dígito de control GTIN, con aviso y opciones
  **«Buscar igual» / «Descartar»** si no cuadra.

### Retirada del escáner por cámara e imagen

- Eliminados `BarcodeScanner.tsx`, la carga de imágenes con ZXing y sus pruebas.
- Eliminadas las dependencias `@tauri-apps/plugin-barcode-scanner`,
  `@zxing/browser` y `@zxing/library`.
- Eliminados el plugin nativo local, el permiso `CAMERA`, el script
  `patch-android-manifest.mjs`, la capability móvil y los pasos de cámara del
  workflow de release.
- La app ya no solicita permisos de cámara ni lee imágenes.

### Verificación

- `npx tsc --noEmit` correcto.
- `npm test`: 62 pruebas en 9 archivos.
- `npm run build` correcto.
- `cargo test`: 25 pruebas.
- `cargo clippy -- -D warnings` correcto.
- Prueba manual en navegador: un EAN del catálogo local selecciona el producto y
  un código con dígito de control incorrecto muestra el aviso de «Buscar igual».

### Nota de actualización

- Si conservas un `src-tauri/gen/android` generado por una versión anterior,
  regenéralo para que el APK local no arrastre el permiso `CAMERA`. En CI el
  proyecto Android se crea desde cero en cada release.
- Queda pendiente probar un lector físico USB/Bluetooth y un Android real; el
  cambio no depende de la cámara ni de permisos del sistema.
