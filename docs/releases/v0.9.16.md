# Better Fitness Tracker 0.9.16

Release de corrección para Linux. No cambia el formato de la bóveda (`omega/`)
ni el de las copias (`longlife/`).

### Cierre limpio del AppImage

- Al cerrar la app desde el AppImage, `WebKitWebProcess` podía abortar
  (`Signal 6 - SIGABRT`) al destruir el contexto gráfico EGL/DMA-BUF de Mesa.
  `systemd-coredump` y DrKonqi registraban el fallo aunque los datos ya
  estuvieran guardados.
- El AppImage ahora fija `WEBKIT_DMABUF_RENDERER_FORCE_SHM=1` antes de
  inicializar GTK/WebKit. La composición sigue siendo acelerada, pero los
  búferes se entregan por memoria compartida y no por la ruta EGL que fallaba
  durante el teardown.
- La mitigación **solo** se activa cuando existe `APPIMAGE`; las builds nativas,
  `.deb`, `.rpm`, Flatpak, Snap, Microsoft Store y Android no se ven afectadas.
- Un valor previo de `WEBKIT_DMABUF_RENDERER_FORCE_SHM` se respeta, incluido
  `0`. Para desactivarla sin recompilar:
  `WEBKIT_DMABUF_RENDERER_FORCE_SHM=0 ./Better-Tracker.AppImage`.

### Verificación

- `cargo check` correcto.
- `rustfmt --check src-tauri/src/main.rs` correcto.
- Comprobado que los procesos `WebKitWebProcess` heredan la variable dentro del
  AppImage y que no se define al ejecutar el binario nativo.

### Nota de actualización

- Los datos existentes se conservan intactos: solo cambia el entorno de
  renderizado del AppImage.
